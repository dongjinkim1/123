# 명령서 — 수용층 융합 생성 v2 (SPEC-RECV-FUSION-v2)

> 사주단독 패턴을 "사주 사건 × MBTI 유형별 수용"으로 끌어올려 진짜 융합을 양산하는 생성 모드.
> 표기: ✅ 실측 검증됨 / 🔧 구현 필요 / ⚠️ 조건부·미해결. 모든 변경은 **하네스 쪽**(production `pattern-data.js`는 RO 무수정).
> 검증 이력: 프로토타입 6회 + 내부 판정자 + 외부 전문가 3회(§7). 외부 전문가 최종 VERDICT: APPROVE(4수정).

---

## 0. 문제와 해법

**문제**: 현 채택 패턴 265개 중 **69%(184개)가 사주단독**(MBTI 태그 0). MBTI 융화율 31%로 기존 production 풀(~81%)보다 훨씬 낮음. MBTS 제품 정체성(사주×MBTI 융합)이 약함.

**왜 융합이 안 됐나 (근본 원인, ✅ 검증)**:
- 하네스에 **트윈 테스트**(card-sampler: 같은 사주·MBTI만 교체)가 있어, "MBTI가 사주 사건을 *일으킨다/부호 바꾼다*"는 주장은 쌍둥이가 같은 답을 내며 **드리프트로 반증**됨. 즉 시스템이 *가짜 인과 융합을 정직하게 거부*.
- 사주 = **사건/운명 엔진**(뭐가·언제·부호), MBTI = **인지 처리 구조**(어떻게 받나) = 다른 층. 인과 융합은 원래 드묾.

**해법**: MBTI가 인과적으로 *살아남는 유일한 층* = **수용·대응**. "사주가 정한 사건을 MBTI 유형이 *어떻게 받고 대응하나*"에 앵커하면 트윈이 갈리고 진짜 융합이 나옴. (✅ 실측: 사주단독 S 1개 → A/S급 융합 4개)

---

## 1. 불변식 (INVARIANTS — 위반 시 반려)

1. **사건 불변**: 사건의 발생·시점·부호는 사주가 정한다. MBTI는 *수용·대응 방식*만 바꾼다.
2. **드리프트 금지**: "MBTI가 사건을 일으킨다/부호를 뒤집는다" = 반려.
3. **트윈 falsifiable**: 같은 사주·다른 MBTI가 *다르게 받아야* 진짜. 같게 받으면(병렬) 병합/반려.
4. **사건 앵커**: 일반 MBTI 서술("INTJ는 원래 X")이 아니라 "*이 사건을* INTJ는 X로 받는다". (트윈이 강제)

## 2. 파이프라인 (단계별 SPEC)

입력: 채택된 사주 패턴 1개(부모). 출력: 유형별 수용 변형 N개(production 스키마).

### 2.1 사건 코어 추출 🔧
- 부모의 사주 태그 중 **support 최대 2태그 부분집합**을 사건 코어로(저차 앵커 — 수용 분할은 +1 MBTI 태그 후에도 support가 floor 이상이어야 함).
- 근거(✅): 4태그 전체+MBTI는 support≈0. 코어 2태그면 코어+MBTI값이 floor 통과.

### 2.2 axis-determination (사건 의존) 🔧 ★핵심
- LLM 1콜: "이 사건의 *수용*이 어느 MBTI 축에서 갈리나?"
- 후보 계열: 지각cf(Se/Ni/Si/Ne) · 판단cf(Te/Ti/Fe/Fi) · 태도I/E(ei:I/E) · 기질kts(NF/NT/SJ/SP).
- 출력은 **정확한 개별 태그**(`cf:Te` 등)만 — 그룹라벨(Je/Ji) 금지. (⚠️ 프로토타입에서 포맷 일탈 1회 → 정규화·검증 필수)
- 사건이 둘 이상 축에서 갈리면 주 축 1개(가끔 2D, 단 support 얇아짐 주의).

### 2.3 수용 변형 생성 (production 8필드) 🔧
- LLM 1콜(ladder식): 선택 축의 각 값별로 *완성 패턴* 생성.
- **production 스키마 출력**: `{name, tags, saju, mbti, cross, falsify}` (id/tier/impact는 후속 부여).
  - `name`: "핵심 — 부제" 1줄
  - `tags`: [사건코어..., 축값] (부분집합)
  - `saju`: 사주조건 서술 1줄
  - `mbti`: 이 유형의 *수용 방식* 1줄. **MBTI 태그 없는 grain이면 `": 없음"`(production 표준), 빈문자열 금지** (✅ 검증: production 160개가 이 형식)
  - `cross`: 사건×수용 교차해설 ~130자
  - `falsify`: 다른 유형은 다르게 받는다는 변별 1줄 (내부 QA·트윈용, production 레코드엔 미수출)

### 2.4 support floor 🔧
- 변형 tags의 holders < **N(운영 8 ≈ 모집단 1%)** → 컷.
- I/E 등 파생 태그는 `mbti` 첫글자로 holders 계산(§3).
- 근거(✅): 과적합(중앙값 support 4) 차단 + 트윈 검증할 실존 인물 보장.

### 2.5 판정 (tier=적합도 + impact 캘리브) 🔧
- **칸별 순차** arbiter 판정(배치 금지 — dedup이 진화하는 accepted셋 대조라 본질 순차, tier도 칸마다 별개). (⚠️ 단 *측정용 매트릭스 테스트*에선 배치 허용)
- `tier` = 기제 신뢰도·falsifiability·적합도. **희소함(낮은 support) ≠ S** (현 풀 S<A support 역전 교정).
- `impact`(1~10) = 유저 의사결정 영향 폭(tier와 직교). **production 841 few-shot 앵커**(i3/5/7/9 실예시)로 캘리브, 7 남발 금지.
  - ⚠️ 한계: 앵커로도 평균오차 ~2, run 노이즈. *진짜 변별 있는 사건*(수용분할)에선 자연 분산(i4~9) — 근사 수용, 정밀 필요 시 production 재채점 보정.
- 반려 축: 바넘(falsify 반대조건서도 성립) / 평면 / 병렬 / 드리프트.

### 2.6 트윈게이트 🔧
- LLM 1콜: 변형들 중 *실질 같게 받는*(병렬·동어반복) 쌍 식별 → 중복 그룹은 best(tier→support) 1개만.
- 근거(✅): distinctness 작동 확인(Ni·Si 병합 등).

### 2.7 매처 drop-in (production 무수정) ✅
- 최종 변형을 production 풀에 그대로 적재 → `matchPatterns`(overlap×impact)가 유저의 MBTI 태그로 *자기 유형 변형*을 top 매칭.
- 유저는 cf 스택 4개를 가지므로 **주기능(fx:_dom) 변형**이 top — 정렬 자연(✅: INFJ → Ni 변형 매칭).
- ⚠️ 정련: raw `cf:`보다 `fx:X_dom`(주기능 위치)으로 분할하면 유저당 변형 1개로 깔끔.

## 3. 축계열 정책 (✅ 4×4 매트릭스 실측 + 외부 전문가)

**우선순위: 판단cf ≈ 지각cf (backbone) > kts (조건부) > I/E (조건부)**

| 계열 | 값 | 정책 | 근거 |
|---|---|---|---|
| 지각cf | Se/Ni/Si/Ne | **기본** | 매트릭스 평균 3.0~3.3, S급 다수(Si·Ni·Ne=S) |
| 판단cf | Te/Ti/Fe/Fi | **기본** | 3.0~3.3. **T/F는 여기로**(2분 금지 — 4분이 변별 우위) |
| kts | NF/NT/SJ/SP | **조건부** | 사건의존: 연애 NT=S/i9, 비견 BBBB. 활성화 사건만 |
| 태도 I/E | ei:I/E | **조건부** | 갈등·조언형 AA(YAD), 구조형 C(LVM). *항상 약한 게 아님 — 사건특이* |

- **T/F·N/S/J/P 원시 2분**: cf 함수로 실현(판단cf=T/F, 지각cf=N/S). 원시 dichotomy 단독은 거칠어 비권장.
- **I/E 태그 신설** 🔧: tag-df 유저 `mbti` 첫글자로 `ei:I`/`ei:E` 파생해 모집단·매처 어휘에 추가(원시 4축 동일 방식). support는 이 파생으로 계산.
- **핵심**: 축은 one-size 아님 — **§2.2 axis-determination이 사건마다 골라야** 함. cf 기본, kts/I-E는 사건이 활성화할 때만.

## 5. 드리프트·품질 가드 (외부 전문가 4수정 반영) 🔧

1. **[HIGH] 인접 드리프트 가드**: kts:SP가 cf:Se의 패러프레이즈로 새는 등(✅ 실측, 판정자가 i4로 자가포착). 변형 cross가 다른 계열 변형과 텍스트 유사도 높으면 강등/재작성.

## 9. 검증자에게 (OPEN QUESTIONS)

1. **사건 코어 2태그 축소가 정당한가** — 4태그 S 패턴의 "사건"을 2태그로 줄여 분할하는 게 원 패턴 의미를 훼손하나, 아니면 수용은 사건 *유형*에 걸리니 OK인가?
2. **impact 정밀도** — 앵커 캘리브 평균오차 ~2가 매처 랭킹(overlap×impact)에 실害인가? production 재채점 보정이 필요한가?
3. **I/E 태그 신설 vs fx 파생** — 원시축 값태그(ei:/tf:/sn:/jp:)를 모집단에 추가 vs 런타임 파생, 어느 쪽?
4. **매처 과집중** — 수용변형이 MBTI 태그 상호배타라 구조적 억제되나, 같은 사건의 여러 계열 변형이 공존하면(지각+판단 둘 다 적재) 과집중 재발하나? 매처 캡(RO) 필요 여부.
5. **sweep과의 관계** — 본 수용분할은 기존 sweep(S급만·고차라 거의 inert, SWEEP-REDESIGN.md §F)과 별개 생성 모드. 둘 다 둘지, 수용분할로 대체할지?
6. **생성 규모** — 사주단독 184개 × (사건별 1~2계열 × 2~4값) = 수백 변형. 쿼터·풀 크기 감당되나, 우선순위 컷 필요한가?
